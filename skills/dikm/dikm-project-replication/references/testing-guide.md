# 垂直切片测试指南

跨项目复制时，每完成一个垂直切片（DB → API → UI）都先验证，再进入下一层。

## 各层验证检查清单

### DB 层

- [ ] 迁移成功执行，无错误
- [ ] 所有表/索引/约束已创建
- [ ] 约束验证：非法数据插入应失败
- [ ] 回滚可用（如适用）

### API 层

- [ ] 端点返回正确响应
- [ ] 认证/授权正常
- [ ] 输入校验拒绝无效数据
- [ ] 错误返回正确的状态码（400/401/404/500）
- [ ] 单元测试 + 集成测试通过

### 前端层

- [ ] 组件正确渲染
- [ ] API 调用成功，数据展示正确
- [ ] 加载态 / 错误态 / 空状态均已处理
- [ ] 用户交互正常（创建/编辑/删除）

### 端到端联调

- [ ] 完整流程走通（从 UI 操作到数据落库再回到 UI 刷新）
- [ ] 数据在各层间一致
- [ ] 无回归（已有功能未受影响）

## 测试模式

```python
# Arrange-Act-Assert
def test_create_entity():
    # Arrange
    data = {"name": "test", "type": "demo"}
    # Act
    response = client.post("/api/entities", json=data)
    # Assert
    assert response.status_code == 201
    assert response.json()["name"] == "test"
```

## 覆盖率参考

| 层 | 目标 | 聚焦 |
|----|------|------|
| DB | N/A | 迁移脚本验证 |
| API | 80%+ | 业务逻辑 |
| 前端 | 60%+ | 关键流程 |
| E2E | 核心路径 | 端到端主流程 |
