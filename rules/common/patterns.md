# 常见模式

> 本文档记录跨语言通用的架构模式和设计决策。语言专用模式见 `java/patterns.md`、`typescript/patterns.md`、`python/patterns.md`。

## 骨架项目

当实现新功能时：

1. 搜索经过实战检验的骨架项目
2. 使用并行代理评估选项：
   * 安全性评估
   * 可扩展性分析
   * 相关性评分
   * 实施规划
3. 克隆最佳匹配作为基础
4. 在已验证的结构内迭代

## 设计模式

### 仓库模式

将数据访问封装在一个一致的接口之后：

* 定义标准操作：findAll, findById, create, update, delete
* 具体实现处理存储细节（数据库、API、文件等）
* 业务逻辑依赖于抽象接口，而非存储机制
* 便于轻松切换数据源，并使用模拟对象简化测试

### API 响应格式

对所有 API 响应使用统一信封格式：成功/状态指示器、数据载荷、错误消息、分页元数据。

### 分层架构

标准三层分离：

* **表现层**：HTTP 端点、CLI 命令、事件处理器 — 负责输入验证和响应格式化
* **业务层**：领域逻辑、用例编排 — 不依赖传输层细节
* **数据层**：持久化、外部服务调用 — 通过仓库/网关抽象

### 错误传播

* 在边界处捕获并转换错误（数据层 → 领域异常 → HTTP 状态码）
* 不吞异常；每层要么处理要么传播
* 向用户暴露最少错误细节，内部记录完整堆栈
